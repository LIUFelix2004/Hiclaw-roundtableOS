# 01_cover

我们做的不是又一个 Agent 编排 Demo，而是让多个智能体真正开一场会。今天想讲清楚三件事：为什么单个模型给的答案没人敢用，我们用圆桌机制怎么解决，以及现场能不能跑给你看。整套系统七个智能体同席、三轮辩论收敛、四维出口质检，全程不需要人工介入。

---

# 02_the_gap

这三个问题是我们真正踩过的。单点视角是根因：一个模型一次推理就给结论，它的盲区就是整个系统的盲区，没有任何环节会提出反对意见。无从追责和不敢落地都是从这里派生出来的。所以我们的判断是，缺的不是更强的模型，而是一个让分歧先发生的场。

---

# 03_the_answer

我们的答案就是 AI 圆桌。七个智能体带着各自的专业视角同时上桌，数据、调研、分析、撰写、质检互相独立，天然形成交叉验证。更关键的是每次发言都必须带立场标签，系统鼓励反对而不是附和。主持人不参与讨论，它只负责控制议程并保证会议开出结果。

---

# 04_mechanism

一场圆桌分四个阶段。主持人开场先锁定议题、成功标准和轮次上限，讨论有边界才收得住。中间是多轮发言，第二轮起参与者被指派质疑或补充，强制产生对立面。第三步主持人把讨论压缩成方案，最后交给质检。轮次上限硬编码为三轮，这是我们对发散不收尾这个老问题的直接回答。

---

# 05_seats_stances

左边是七个席位和各自的职责，颜色和产品里的实时界面是一致的。右边是立场标签，这是圆桌和普通群聊式多智能体最大的区别：发言必须表态，是提案、质疑、补充还是收敛。第二轮起系统会轮流指派质疑方和补充方，确保每个提案都至少被正面挑战过一次。

---

# 06_three_rounds

这是同一个议题在三轮里的演进。第一轮各自提案，观点是平行的。第二轮开始交锋，质疑方直接指出口径问题，补充方修正节奏判断。第三轮不再引入新议题，只围绕活下来的方案补齐执行细节。观点的质量是在对抗中提升的，这一页是整个机制价值的直接证据。

---

# 07_synthesis

收敛这一步决定了圆桌是不是白开。主持人不复述讨论，而是把全部发言压缩成四段式结构化结果：共识、分歧、执行任务、风险项。注意我们保留分歧而不假装一致。最右边的执行任务清单带负责人、输入和交付标准，可以直接喂回任务流水线由调度器接着跑。

---

# 08_firewall

圆桌讨论出来的方案没有豁免权。共识必须通过 Validator 的四维评分才允许发布，任何一维不合格都是一票否决。不通过时校验失败码会直接驱动回滚，主持人重新合成，最多五轮仍不过才升级为人工工单。这条闸门同样作用于每一个智能体的中间产出，圆桌只是它守住的最后一道。

---

# 09_stage_3d

这是现场最有记忆点的部分。多智能体最难被感知的是同时性，谁在等、谁在想、谁在反对，平铺的聊天流表达不了，一张桌子可以。场景用 Three.js 渲染，七个席位环绕圆桌可以自由旋转，思考态有头部摆动和光环脉冲，发言气泡会停留在座位上方。这里可以直接切到实机演示。

---

# 10_the_base

圆桌敢用，是因为下面有一整套底座。一场会议开得好不好，取决于参会者靠不靠谱、失败能不能兜住、过程能不能查。协作层就是刚才讲的圆桌，接下来三页快速交代其余三层：能力怎么装、失败怎么救、过程怎么查。

---

# 11_skill_dag

先说能力怎么装。每个智能体只声明五个文件，能力声明、提示词、输出结构、校验和工具绑定，调度、重试、观测全部由运行时托管，新增一个角色不用写一行调度代码。右边是任务调度器，用拓扑排序自动分层，同层并行执行，上游产出自动注入下游上下文。调度器不理解业务，只理解依赖。

---

# 12_resilience

失败怎么救。四级阶梯从最便宜的开始：先试快照回滚，复用最近一次通过校验的输出，零 Token 成本；再按经验记忆的历史成功率换模型重跑；然后原模型重试；都不行才生成带操作建议的人工工单。右边的经验记忆让这套阶梯越用越准，每次成败都会改变下一次先试哪个模型。

---

# 13_observability

过程怎么查。每次执行都会经过八个阶段并逐一埋点，带模型、Token、成本和耗时。这里要强调因果关系：可观测不是事后补的日志，它是回滚决策的输入，没有 Trace 和快照就没有自动恢复。下面三张卡分别是快照留痕、成本归集和运行看板。

---

# 14_demo

演示议题选了一个真实会有分歧的问题：储能、光伏、新能源车三条主线哪条最值得优先配置。这个议题不同角色会给出不同答案，正好能看出圆桌的价值。需要说明的是，演示数据是仓库内置的模拟数据集，字段结构与真实数据源一致。开启 Mock 模式后没有 API Key 也能跑通整场圆桌。

---

# 15_why_us

和常见方案的差别，最上面一行是最关键的：别人的多智能体是链式调用或主从分发，角色之间不交锋，结论仍然来自单个模型的一次推理；我们的结论是多视角对抗之后被保留下来的部分。下面四行是让这件事可靠的配套。我们不打算取代编排框架，补的是它们普遍留白的那两层，对抗与治理。

---

# 16_closing

下一步我们想把这场会议变成一套会议制度：主持人根据议题复杂度自行决定轮次和参会角色，能力可以像插件一样灰度上线让圆桌自由组队，再加上预算护栏让长辩论也花得可控。谢谢，欢迎提问，也欢迎现场看实机演示。
